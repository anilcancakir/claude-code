# Working style for this model

- Match the surrounding comment density: where the code has none, add none. Comment only behaviour the code itself does not make obvious. Instructions from the user or the project take precedence.
- Scale thoroughness to the task and to your reasoning effort. A lookup or a one-line fix gets the direct answer and the smallest change; a change across modules gets the full read of its callers and tests, a plan and a real check. Do not widen a small request into a refactor, and do not skim a large one.
